# 0017 — The knowledge base and the artifacts of building it are two directories

Status: Accepted (2026-08-21). Renames `agent/kb/` to `agent/animation_knowledge_base/` and moves what
only the build produced into a sibling, `agent/motionkb_build/`. Refines the layout
[0012](0012-accepted-store-in-its-own-directory.md) and
[0016](0016-one-store-status-is-the-membership-test.md) settled; no record's content changed and no
decision in either is reversed. Fixes a latent defect in `AgentRuntimeSetup.BuildClipLibrary`, below.

## Context

`agent/kb/` held eleven things and a reader could not tell which of them were the knowledge base:
`actions/` next to `_reports/`, the live v2 contract next to the retired v1 one, the records next to a
snapshot of records the pipeline no longer produces. The `_` prefix marked "generated", which sorted
build reports and the pose dumps every measured number is computed from into the same class — a
distinction that stopped being useful once almost everything in there was generated by something.

`kb` also said less than it could. This project has one knowledge base, and it is about animation.

The question this split turns on is not "was it generated" but **who reads it**:

- `kb_pose` indexes into a `raw` dump to measure a moment. `agent/transitions.py` and
  `agent/segments.py` derive the seam and segment tables from those dumps and fingerprint against
  them. The agent's `read` tool returns a rendered frame as a picture to look at. `paths.accepted_files`
  reads the manifest at every start. `agent/assemble.py` codes to `engine_mask_map.json`.
- Nothing at runtime opens a run report, the corpus enumeration, the retired v1 schema, or the
  superseded authoring snapshot.

The second group was also *visible to agentic search*, which is worse than untidy. Measured before the
change: `grep("walking")` returned eight files, seven of them not records; `grep("body_parts")`
returned the retired v1 contract and nothing else. `_authored_claude_backup` was already special-cased
out by name in `agent/tools/files.py` for exactly this reason — a stale record looks exactly like a
current one — which is a denylist standing in for a boundary that did not exist.

## Decision

**Two directories, split by who reads them.**

```
agent/animation_knowledge_base/     everything a CONSUMER reads
├── actions/                all 2454 records
├── raw/                    frozen per-frame pose dumps
├── frames/                 rendered evidence frames
├── derived/                segment and transition tables
├── manifest.json           index of the accepted records
├── engine_mask_map.json    9 channels -> Unity AvatarMask
├── schema/                 the live contract (motionkb.v2) + its CHANGELOG
└── README.md

agent/motionkb_build/               everything that exists only because it was BUILT
├── reports/                run reports + the corpus enumeration `sample` resumes from
├── archive/                the superseded authoring snapshot, the retired v1 contract
└── retrieval_eval_set.json what retrieval is expected to return
```

**`raw/` and `frames/` are knowledge, not build output.** They are the only inputs to the MEASURED and
SEMANTIC halves respectively, and the runtime reads both. Splitting them out would have put 1.4 GB
somewhere tidier at the price of the runtime reaching across the boundary for its own data — which is
the coupling a split exists to remove. The evidence behind a record belongs with the record.

**The `_` prefixes go.** They meant "generated", and the directory a thing lives in now says what it
is for. `kb_manifest.json` becomes `manifest.json`: it is in the knowledge base, so the prefix was
repeating its own address.

**`motionkb_build/` is not mounted into the agent's search workspace.** `EXCLUDED_DIRS` in
`agent/tools/files.py` is empty as a result, and kept for something superseded that cannot move.
Unreachable is a stronger property than skipped-by-name, and it needs no list to stay in sync.

**`paths.py` grows `BUILD_DIR`** (`MOTIONKB_BUILD_DIR`, defaulting to a sibling of `MOTIONKB_DIR`), plus
`DERIVED_DIR`, `ENGINE_MASK_MAP`, `ARCHIVE_DIR` and `EVAL_SET`. Everything that hardcoded a subdirectory
name now asks paths for it, which is what made this a mechanical change rather than a search.

## Consequences

What the agent sees at `read('.')` is unchanged — the mount is still named `kb`, because the workspace
is virtual and a model typing paths is better served by four characters than by twenty-five. What
changed is what is under it.

Gates after the move: validator **2454 passed / 0 failed**, golden re-extraction **8/8**, manifest in
sync, guid→asset **8 resolved / 0 failed** live against the running editor. Agent suite **349 passed**.
Unity recompiled clean.

**A defect this surfaced, in `AgentRuntimeSetup.BuildClipLibrary`.** It globbed `*.json` at the KB root
and skipped three shared files by name. Since [0012](0012-accepted-store-in-its-own-directory.md) moved
the records down into `actions/`, the only `*.json` at the root *were* those three — so it had been
building an empty `ClipLibrary` and saying nothing, because an empty library is indistinguishable from
one nobody asked about. It now reads `manifest.json`, which indexes exactly the accepted records and
already carries the identity it needs, so it opens no record at all. The denylist is gone with it: this
was the last consumer still carrying the one ADR 0012 was written to delete.

**Two git tags now point at a third layout.** `kb/v1` and `kb/v2` hold the KB at `Assets/MotionKB/`,
which was already stale after the move to `agent/kb/`; this makes the documented rollback further from
a checkout and closer to a manual reconstruction. Not fixed here, and not made materially worse — a
rollback across a directory rename was already a rename either way.

**Doc paths were rewritten wholesale, including inside dated notes.** A path in a document is a pointer
to a live thing, not a claim about history: "the store was promoted on 2026-06-24" stays true while its
path has to keep resolving. 180 pointers across 15 documents.

## Alternatives considered

**Keep everything in one directory and just rename it.** The name was the smaller half of the problem.
A reader opening `animation_knowledge_base/` and finding a run report beside the records learns the
same wrong thing they learned from `kb/`.

**Put only `actions/` and `frames/` in the knowledge base** — the literal reading of "the structured
actions and their rendered frames". Rejected on a measurement: `kb_pose`, the seam table and the
segment table all read `raw/` at runtime, and the manifest is read at every agent start, so this draws
the boundary straight through the runtime's own data. It would also keep the frames and separate the
dumps, when both are the same kind of thing — frozen evidence, one for the eye and one for the
arithmetic.

**Leave the archive inside and keep the denylist.** It worked, and it will keep working right up until
someone adds a second superseded directory and forgets the list. The move makes the guarantee
structural.

**Also move `derived/` out.** They are generated tables, so "was it generated" would put them in the
build directory. But `agent/segments.py` and `agent/transitions.py` read them to answer questions about
motion, which is the test that matters here.
